# Deploying the Event Management MVP

Recommended for the course: **Render** (free tier) — one **PostgreSQL** database + one **Web Service** that runs the API and serves the built React app.

## Architecture (single service)

```
Browser → https://your-app.onrender.com
            ├── /api/*     → FastAPI
            └── /*         → React static files (Vite build in backend/static)
```

No CORS headaches: frontend and API share the same origin.

---

## Prerequisites

- GitHub repo pushed (Render deploys from Git).
- [Render](https://render.com) account.

---

## Step 1 — Create PostgreSQL on Render

1. Dashboard → **New +** → **PostgreSQL**.
2. Name: `event-mgmt-db`, database: `event_mgmt`, region near you, **Free** plan.
3. Create → open the DB → copy **External Database URL** (starts with `postgresql://`).

---

## Step 2 — Load schema and seed (once)

From your machine (needs `psql`):

```bash
cd "/path/to/DB Project"
export DATABASE_URL='postgresql://USER:PASS@HOST/event_mgmt'   # paste from Render
chmod +x scripts/bootstrap_remote_db.sh
./scripts/bootstrap_remote_db.sh
```

Fresh empty DB only. If you re-run on the same DB, you will get duplicate-key errors.

---

## Step 3 — Deploy the web service

### Option A — Blueprint (repo includes `render.yaml`)

Use this if you **already created Postgres on Render** and do not want a second database.

1. Dashboard → **New +** → **Blueprint**.
2. Connect your GitHub repo (uses `render.yaml` — **web service only**, no new DB).
3. After the blueprint finishes, open **event-management** → **Environment**.
4. Set **`DATABASE_URL`** to your existing Postgres **Internal Database URL** (from the DB you created earlier).
5. Save → **Manual Deploy** if needed.

`JWT_SECRET` is auto-generated by the blueprint.

**Local Postgres on your Mac** is not used by Render. For deploy, either load seed data into your **Render** DB (`bootstrap_remote_db.sh` with Render’s URL) or keep local DB for development only.

### Option B — Manual web service

1. **New +** → **Web Service** → connect repo.
2. Settings:
   - **Root Directory:** `backend`
   - **Runtime:** Python 3
   - **Build Command:**
     ```bash
     pip install -r requirements.txt && cd ../frontend && npm ci && npm run build && rm -rf ../backend/static && cp -r dist ../backend/static
     ```
   - **Start Command:**
     ```bash
     uvicorn app.main:app --host 0.0.0.0 --port $PORT
     ```
3. **Environment variables:**

   | Key | Value |
   |-----|--------|
   | `DATABASE_URL` | Internal DB URL from Render Postgres (or external) |
   | `JWT_SECRET` | Long random string (32+ chars) — **required** |
   | `CORS_ORIGINS` | Optional if same-origin; for local testing add `http://localhost:5173` |

4. **Create Web Service** → wait for build (first build ~5–10 min on free tier).

---

## Step 4 — Verify

1. Open `https://YOUR-SERVICE.onrender.com/api/health` → `{"status":"ok"}`.
2. Open `https://YOUR-SERVICE.onrender.com/` → sign-in page.
3. Log in as guest: `alex.m@student.edu` / `demo123`.
4. Log in as organizer: `hello@nlevents.eu` / `demo123`.

Free tier services **spin down** after ~15 min idle; first request may take 30–60 seconds.

## Local production-like test

```bash
# Terminal 1 — API + static (after building frontend)
cd frontend && npm ci && npm run build && cp -r dist ../backend/static
cd ../backend && source .venv/bin/activate
export DATABASE_URL=postgresql://localhost:5432/event_mgmt
export JWT_SECRET=$(python -c "import secrets; print(secrets.token_hex(32))")
uvicorn app.main:app --host 127.0.0.1 --port 8000

# Open http://127.0.0.1:8000
```

## Split hosting (optional)

| Piece | Host | Env |
|-------|------|-----|
| Frontend | Vercel / Netlify | `VITE_API_BASE_URL=https://your-api.onrender.com` |
| API | Render web service (no `static/` copy in build) | `CORS_ORIGINS=https://your-app.vercel.app` |
| DB | Render / Neon / Supabase | `DATABASE_URL` on API |

Build frontend: `cd frontend && npm run build`, deploy `dist/`.

---

## Security checklist

- Never commit `.env` or real `DATABASE_URL` / `JWT_SECRET`.
- Use a strong `JWT_SECRET` in production.
- Rotate demo passwords before a public demo if the DB is exposed.

---

## Troubleshooting

| Problem | Fix |
|---------|-----|
| Build fails on `npm` | Ensure Render build includes `cd ../frontend`; Node is available on Python native runtime. |
| **`POST /api/auth/register` → 500** but `/api/health` is OK | Web service has no working DB. Open `https://YOUR-APP.onrender.com/api/ready` after redeploy — it returns a clear 503 message. Set **`DATABASE_URL`** on the **web service** (Internal URL from your Render Postgres), then run `scripts/bootstrap_remote_db.sh` once with the **External** URL from your laptop. |
| `relation does not exist` | Run `scripts/bootstrap_remote_db.sh` against hosted `DATABASE_URL`. |
| 401 on all API calls | Check `JWT_SECRET` is set on the service (not the default dev value). |
| Blank page, API works | Rebuild and ensure `backend/static/index.html` exists after build. |
| CORS errors (split deploy) | Set `CORS_ORIGINS` to exact frontend URL including `https://`. |
